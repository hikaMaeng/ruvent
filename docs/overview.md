# 개요

ruvent는 이벤트 서버다. 서버는 일곱 개의 메서드를 제공하고, 그 위의 정책(재시도, 실패 처리, 후속 일)은
메서드를 부르는 쪽(워커)이 갖는다. 설계 근거와 사용자 원문은
[재설계 제안서](proposals/event-server-redesign.md) 2장에 있다.

## 하는 것

| 메서드 | 동작 |
| --- | --- |
| 1 착수용 등록 | 대기 상태로 큐에 넣고 작업 키를 준다. 그 채널 구독자에게 착수 가능 알림(머리 + 작업 키) |
| 2 발송용 등록 | 그 순간의 채널 구독 접속에 넘기고 끝. 저장하지 않는다 |
| 3 착수 마킹 | 대기 중이면 엔벨롭의 착수 블록(표지, 착수자, 워커 표지, 기한)을 채운다. 응답은 엔벨롭 전체 |
| 4 완료 보고 | id·표지·자격이 현재 착수와 맞으면 지우고, 실린 후속 이벤트를 같은 스텝에 등록한다. 성공·실패를 구분하지 않는다 |
| 5 삭제 | 대기 중일 때만 지운다. 결과 채널에 성공·실패 발송 이벤트를 정확히 한 건 낸다 |
| 6 구독 | 채널 구독자로 등록하고, 대기분을 작업 키 순으로 한 페이지 준다 |
| 7 구독 취소 | 이 처리 이후의 발송은 받지 않는다 |

* **착수 기한은 스케줄러 없이 처리한다.** 배치의 첫 외부 등록(메서드 1·2) 직전에 기한 지난 착수를 모두
  대기로 되돌린다. 재시도 카운트를 하나 올리고 id를 재발급한다. 늦게 온 완료는 그 id가 없으므로 무효다.
* **저널.** 미처리 착수용 이벤트를 순변화로 기록하고 재기동 때 다시 올린다. 착수 중이던 것은 대기로 되돌리고
  id를 재발급하며 재시도 +1을 준다. 설정이 있으면 고른 채널을 운영 스냅샷 파일로 모은다.

## 하지 않는 것

* 재시도 상한, dead letter, 실패 결과 자동 생성, 리액션 표, 트랜잭션 키 멱등, 보존 로그, 범위 읽기.
  모두 워커 쪽 로직이거나 없앤 것이다.
* 발송용 이벤트의 재전송. 끊겨 있던 접속은 그동안의 발송을 받지 못한다(Q8).
* 외부 효과의 중복 방지. 회수 뒤 다른 워커가 같은 일을 다시 할 수 있다. 워커는 작업 키로 거른다(G3).
* payload 해석. 코어는 JSON을 모른다.

## 보장 계약

| # | 보장 |
| --- | --- |
| G1 | 대기 중인 착수용 이벤트에 여럿이 착수하면 정확히 하나만 성공한다 |
| G2 | 완료는 id·표지·착수 당시 서비스 자격이 맞을 때만 반영된다. 회수·재기동·경합 패배 뒤의 보고와 이미 반영된 완료의 재전송은 후속과 함께 무효다 |
| G3 | 작업 키는 등록 건마다 부여되고 회수·재기동에도 유지된다 |
| G4 | 대기·착수 중인 착수용 이벤트는 저널 내구화 지점을 기준으로 재시작을 넘는다. Strict는 등록·완료·삭제의 성공을 디스크 기록 뒤에 알린다. 착수는 기다리지 않는다 |
| G5 | 발송용 이벤트는 등록 처리 순간의 구독 접속에 넘겨지고 그 순간 사라진다. 버퍼가 가득 찬 접속은 끊긴다 |
| G6 | 서버는 어떤 접속의 송신도 기다리지 않는다 |
| G7 | 삭제는 대기 중일 때만 성공하고, 결과 통지는 정확히 한 건이다 |
| G8 | 착수용 큐에 있는 id로는 어떤 이벤트도 등록되지 않는다(후속끼리도). 큐를 떠난 id는 다시 쓸 수 있다 |

각 보장의 테스트는 [testing.md](testing.md)의 "보장 ↔ 테스트" 표에 있다.
