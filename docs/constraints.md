# 제약과 보장

## 보장하는 것

| 보장 | 조건 |
| --- | --- |
| 한 메시지는 한 번에 한 소비자에게만 있다 | 항상 |
| 한 `transaction_key`는 한 번에 한 워커만 실행한다 | 항상 |
| 밀려난 시도는 로그에 쓰지 못한다 | 항상 (엔진이 시도 번호로 판정) |
| 사실과 그것이 부른 일감은 함께 존재하거나 함께 없다 | 항상 (같은 스텝) |
| 결과 기록과 메시지 삭제는 함께 일어난다 | 항상 |
| `position`은 모든 채널에 걸쳐 커밋 순서이고 재시작 뒤에도 커지기만 한다 | 항상 |
| 저널 쓰기는 겹치지 않고 순서를 건너뛰지 않는다 | 항상 (상태·사슬·잠금 파일) |
| 저널 배치는 전부 남거나 전부 없다 | 프레임 CRC |
| 메모리와 저널 파일은 한정된다 | `Retention`, `Compaction`. 정상 종료 뒤 저널은 압축 임계 이하 |
| 저널이 아닌 파일은 열지 않고 건드리지 않는다 | 파일 머리(이름 + 형식 버전) |
| 유휴 중에는 엔진이 깨어나지 않는다 | 걸린 기한이 없을 때 |

## 보장하지 않는 것

**응답한 것이 디스크에 있다는 것 (기본값).** `Durability::Scheduled`에서 크래시는 마지막으로
완료된 저널 쓰기 이후의 변화를 잃는다. 기본 창은 100ms다. 지금 안 적힌 변화의 수는
`Engine::stats().journal_lag`로 본다.

| 잃은 것 | 결과 |
| --- | --- |
| "메시지 없음" 선언 | 메시지가 다시 전달되고, 그 스텝이 다시 실행된다 |
| "메시지 있음" 선언 | **명령이 사라진다.** 클라이언트가 같은 `transaction_key`로 다시 보내야 한다 |
| 시도 횟수 증가 | 그 시도가 세어지지 않는다 |

잃으면 안 되는 지점에서는 `Engine::flush().await`를 부르거나 `Durability::Strict`를 쓴다.

**재시작을 넘는 이벤트.** 기본값에서 이벤트는 메모리에만 있다. 재시작하면 로그는 비어 있고,
이전 커서로 재개한 구독은 `lagged()`가 참이 된다. 남겨야 하는 채널은 `Events::Channels`로 지정한다.

**재시작을 넘는 중복 제거.** 끝난 실행은 기본값에서 메모리에만 기억된다(창 10분). 재시작
뒤에 같은 키로 다시 온 명령은 다시 실행된다. `Persist::settled`를 켜면 창 안에서는 막는다.

**보존 기간을 넘는 사실 중복 제거.** 같은 `key`의 사실은 로그에 남아 있는 동안만 하나로 합쳐진다.
`Retention`이 그 사실을 메모리에서 내보낸 뒤 재실행이 같은 사실을 다시 기록하면 새 이벤트가 되고,
리액션도 다시 발급된다. 재생은 같은 id의 앞선 기록을 나중 기록으로 대체하므로 로그에 둘이 되지는 않는다.

**exactly-once.** 전달은 at-least-once다. 핸들러는 재실행을 전제해야 한다.

**다중 프로세스·다중 장비.** 엔진 하나는 프로세스 하나다. 저널은 한 엔진만 연다.

**무한 이력.** 로그는 `Retention`으로 한정된다. 영구 이력이 필요하면 사실에 반응하는
서비스로 자기 저장소에 투영한다.

## 핸들러가 지켜야 하는 것

* **한 가지를 하고 끝낸다.** 반복과 분기는 리액션으로 표현한다.
* **기한 안에 끝낸다.** 기본 10분. 넘으면 future가 drop되고 다시 실행된다.
* **CPU 작업은 `spawn_blocking`으로.** 핸들러는 async 풀에서 돈다.
* **재실행을 전제한다.** 사실은 `key`로 정체성을 준다. 스트리밍 델타는 줄 수 없으므로 펜싱에 맡긴다.
* **기록이 아닌 부수효과 직전에는 `cx.fence()`.** 프로세스 실행, 외부 전송, 과금.
* **소유권을 future에 묶는다.** 자식 프로세스는 kill-on-drop으로 둔다.

## 결정 기록

| 결정 | 이유 | 대가 |
| --- | --- | --- |
| PostgreSQL/PGMQ를 쓰지 않는다 | 원본 지연의 대부분이 DB 왕복이었다. 큐 잠금은 단일 작성자로 대체된다 | 다중 프로세스 확장 |
| 기본 내구성은 뒤따라 쓰는 저널 | 이벤트 큐는 입출력이 잦다. 연산마다 fsync를 기다리면 처리량이 디스크에 묶인다 | 크래시 시 마지막 창 |
| 저널은 순변화만 | 들어왔다 끝난 일을 적을 이유가 없다 | 이력으로서의 저널은 없다 |
| 이벤트와 진행 로그는 기본적으로 적지 않는다 | 기계는 큐만 있으면 이어간다 | 재시작 뒤 로그가 빈다 |
| 리스·heartbeat가 없다 | 한 프로세스 안에서는 감독 태스크가 즉시 안다 | 원격 워커를 붙이려면 다시 필요하다 |
| 이벤트 하나는 워커 하나 | 한 실행에 여럿이 얹히는 수명 관리를 없앤다 | 같은 키의 두 번째 제출은 별도 응답을 받지 않는다 |
| 저널 실패는 종료 | 실패한 쓰기 뒤의 파일 상태는 알 수 없다 | 디스크 오류가 곧 서비스 중단 |
| 커서는 클라이언트가 든다 | 서버 커서 테이블과 이벤트마다의 갱신이 없다 | 클라이언트가 위치를 기억해야 한다 |
| payload는 바이트 | 코어는 JSON을 모른다 | 타입 검사는 핸들러의 일 |
| 식별자는 xxh3 | 이벤트당 고정 비용 | 원본 TS와 식별자가 일치하지 않는다 |
