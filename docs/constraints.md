# 제약과 대가

결정된 사항과 그 대가다. 바꾸려면 제안서의 해당 결정부터 다시 연다.

| 제약 | 대가 | 근거 |
| --- | --- | --- |
| 단일 작성자 엔진 | 큐 연산은 한 코어. 이벤트당 비용을 줄이는 것이 1차 대응 | 4.1 |
| 회수는 외부 등록 때만 | 등록이 끊긴 동안에는 기한 지난 착수도 회수되지 않는다. 그동안 삭제하려 하면 아직 착수 중이므로 실패한다 | 6.4, 원문 |
| 접속이 끊긴 워커의 착수는 기한으로 회수(Q6 (b)) | 회수가 다음 등록까지 늦다. 대신 접속별 착수 목록을 유지하지 않는다 | Q6 |
| Strict에서도 착수·회수는 디스크를 기다리지 않는다 | 착수 기록 전에 서버가 죽으면 재기동 뒤 재시도 카운트가 하나 적을 수 있다(Q7의 +1 누락) | 6.5 |
| 늦은 완료의 마감은 실제 회수(Q10 (a)) | 기한이 지났어도 회수 전이면 표지가 맞는 완료를 받는다 | Q10 |
| id는 큐에 있는 동안만 고유 | 완료 뒤 같은 id의 재전송은 새 이벤트로 받는다. 필요하면 워커가 작업 키로 거른다 | 원문, G8 |
| 발송은 등록 순간의 구독자에게만 | 끊겨 있던 접속은 놓친다. 버퍼 포화는 연결 종료로 알린다 | 원문, G5, Q8 |
| 저널 형식 v2 | v1 파일은 `InvalidData`로 거부하고 바이트를 보존한다. 변환 도구는 없다(Q9 (a)) | 6.7 |
| 세대 카운터 u32 | 다 쓰면 서버가 기동을 거부한다(약 43억 번의 기동·순번 소진) | 6.0 |
| 재시도 카운트 u16 | 65,535에서 멈추고 "그 이상"을 뜻한다 | 6.0 |
| `principal`은 서비스 자격(Q11 (a)) | 같은 프록시를 쓰는 사용자 둘은 같은 `principal`을 갖는다. 최종 사용자는 별도 필드 `delegate`(플래그 비트 5) | Q11 |
| 서버 사전은 쓸어내기로 정리 | 쓰이지 않는 이름이 다음 쓸어내기까지 남는다(상한 `2 × 생존 + 1024`) | 6.0 |
| 수신 버퍼 조각 공유 | 작은 payload가 큰 수신 버퍼를 오래 붙잡을 수 있다. 분리 복사는 아직 넣지 않았다 | 6.0, 10장 |
| 워커 lease 초과 | 핸들러를 버리고 완료하지 않는다. 회수는 서버가, 포기 여부는 `max_retries`가 정한다 | 6.6 |
