# 제약과 대가

결정된 사항과 그 대가다. 바꾸려면 제안서의 해당 결정부터 다시 연다.

| 제약 | 대가 | 근거 |
| --- | --- | --- |
| 서버 하나 = 단일 작성자 장부 하나, 서버 안 분할·복제 없음 | 용량과 가용성은 독립 서버 수로 얻는다. 서버를 잃으면 그 서버의 대기 이벤트는 재기동까지 기다리고, 디스크를 잃으면 잃는다 | 계획 0.3, 2.8 |
| 큐 구조 (가): tokio 태스크 + `mpsc` | 코어별 스레드·링은 측정(M0)이 요구할 때 넣는다 | 계획 2.2 |
| 착수용 이벤트는 최소 1회 실행 | lease 만료, 완료 유실, 비정상 종료는 재실행을 낳는다. 워커의 업무 멱등이 필수다 | 계획 0.3 |
| 활성에서 빠진 뒤의 재전송은 서버가 막지 않는다 | 순번을 잇는 생산자는 순번이, 그 밖은 워커의 업무 멱등이 막는다. 키 창은 없다 | 계획 2.3, 7장 |
| 발송은 등록 순간의 구독자에게만 | 구독자가 없거나 끊겨 있으면 사라진다. 요청의 결과도 발송이다(요청별 채널). 결과를 지킬지는 워커와 프로젝트가 정한다 | 계획 2.8(v4.8) |
| 채널은 이름 없는 UUIDv7뿐 | 계층·접두사·패턴이 없다. 채널 묶음을 한 번에 구독하거나 채널 이름으로 권한·설정을 걸 수 없다. 묶음이 필요하면 타입으로 고르거나 서버를 나눈다 | 계획 9.14(v4.9) |
| 설정·권한·스냅샷·정지는 타입(u16) 기준 | 같은 타입이면 채널이 달라도 같은 규칙이다. 구독은 채널을 아는 쪽이 하고, 넘겨받는 것은 자격의 타입뿐이다 | 계획 9.14(v4.9) |
| 타입 참여의 배정 비용 | 타입 참여 하나가 창을 채울 때 그 타입의 대기 줄마다 머리 하나를 본다. 줄은 대기가 있는 동안만 있다 | 계획 9.14(v4.9) |
| 늦은 완료의 마감은 실제 회수 | 기한이 지났어도 회수 전이면 표지가 맞는 완료를 받는다 | Q10 |
| 저널 형식 5, 세그먼트 디렉터리 | 형식 4 이하와 단일 파일은 거부하고 바이트를 보존한다. 변환 도구는 없다 | 계획 B12 |
| 휘발 타입은 디스크를 쓰지 않는다 | 넘치면 뿌리 타입 정지가 받는다. 예외는 예약분을 다 쓴 순간의 휘발 후속 본문이고 재기동 때 버린다 | 계획 B15 |
| 메타는 내리지 않는다 | 관리 메모리가 대기 수에 비례한다. 대기 깊이 목표(S22)를 넘으면 콜드 메타를 내리는 일이 필요하다 | 계획 B11 |
| 디스크 용량은 설정이다 | `StorageConfig::disk_capacity`가 없으면 디스크 예산·고수위·이주 계기가 서지 않는다(사용량은 센다) | std로 파일 시스템 용량을 물을 수 없다 |
| 실패 횟수 u16 | 65,535에서 멈추고 "그 이상"을 뜻한다 | 6.0 |
| `principal`은 서비스 자격(Q11 (a)) | 같은 프록시를 쓰는 사용자 둘은 같은 `principal`을 갖는다. 최종 사용자는 별도 필드 `delegate` | Q11 |
| 조용한 끊김은 커널 keepalive가 안다 | 감지에 약 30초(S13)가 걸린다. 앱 heartbeat는 없다 | 계획 2.2 |
